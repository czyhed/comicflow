# ref2va 级联功能验证测试故事

## 测试目标

验证在连续多个镜头中：
1. ✅ 使用上个镜头的尾帧（保证画面连贯）
2. ✅ 同时使用角色参考图（保证角色外观一致）
3. ✅ 使用 MiniMax H3 的 `ref2va` 模式而不是 `i2va`

## 推荐测试故事

### 故事 1: 简单对话场景（最小验证）

**场景描述**：两个角色在咖啡馆对话

**角色设置**：
- **角色 A - 小明**：年轻男性，黑色短发，戴眼镜，穿蓝色衬衫
- **角色 B - 小红**：年轻女性，长发，穿白色T恤

**分镜脚本**：

```
场景1：咖啡馆内部，白天

镜头1：
- 角色：小明
- 动作：小明坐在桌前，拿起咖啡杯
- 对白：小明："今天天气真不错。"
- 时长：5秒

镜头2：
- 角色：小明
- 动作：小明放下咖啡杯，微笑看向对面
- 对白：小明："你觉得呢？"
- 时长：5秒

镜头3：
- 角色：小红
- 动作：小红点头回应
- 对白：小红："是啊，很适合出去走走。"
- 时长：5秒

镜头4：
- 角色：小明, 小红
- 动作：两人同时起身准备离开
- 对白：小明："那我们走吧！"
- 时长：5秒
```

**为什么选这个**：
- ✅ 角色在多个连续镜头中出现
- ✅ 测试单角色和多角色场景
- ✅ 简单易验证，生成速度快

## 操作步骤

### 1. 准备角色参考图

为每个角色准备一张参考图：

**方法 A：使用 AI 生成**
```
打开 ComicFlow 前端
→ 进入"角色管理"
→ 创建角色
→ 输入角色描述
→ 点击"生成参考图"
```

**方法 B：上传自己的图片**
```
准备角色图片（建议 720x1280 或相近比例）
→ 在"角色管理"中上传
```

### 2. 创建项目和剧本

```
1. 创建新项目
2. 添加角色（确保上传/生成了参考图）
3. 输入上面的分镜脚本
4. 或使用 AI 助手生成剧本
```

### 3. 生成视频

```
1. 点击"生成视频"
2. 确保选择了 MiniMax H3 提供商
3. 等待所有镜头生成完成
```

### 4. 验证结果

#### 4.1 查看生成日志

```bash
# SSH 到服务器（如果是生产环境）
ssh user@your-server

# 或在本地查看 Docker 日志
docker compose logs -f worker | grep -E "ref2va|i2va|reference|cascade"
```

**期望看到的日志**：
```
[INFO] Shot 2: h3_reference_reanchor=True (使用 ref2va 模式)
[INFO] Adding continuity_reference from previous shot
[INFO] Including character reference images: ['character_c1_ref.jpg']
[INFO] Using MiniMax H3 ref2va mode with tail frame + character refs
```

**不应该看到的日志**：
```
[INFO] Using i2va mode (cascade without character references)  ❌ 错误
[INFO] Removing character references for cascade  ❌ 错误
```

#### 4.2 视觉检查

观看生成的视频，检查：

✅ **画面连贯性**：
- 每个镜头的开始画面与上一个镜头的结束画面相似
- 背景、光照保持一致
- 没有突兀的场景跳跃

✅ **角色一致性**：
- 角色的外观（发型、服装、面部特征）在所有镜头中保持一致
- 角色的风格与参考图匹配
- 多角色场景中，每个角色都清晰可辨

❌ **失败的表现**（说明没有使用 ref2va）：
- 角色外观在不同镜头中变化很大
- 角色风格不统一
- 角色与参考图差异明显

### 5. 对比测试（可选）

如果想对比修改前后的差异：

```bash
# 临时关闭新功能，使用旧的 i2va 逻辑
# 在服务器 .env 中添加：
FORCE_USE_I2VA_CASCADE=true

# 重启服务
docker compose restart worker

# 用同样的故事生成一次
# 对比两次生成的角色一致性
```

## 预期测试结果

1. **日志显示**：

   - 画面虽然连贯但角色不一致

## 故障排查

如果测试不通过：

```bash
# 1. 检查环境变量
docker compose exec api env | grep MINIMAX

# 2. 确认使用了 H3
USE_MINIMAX_H3=true

# 3. 检查角色是否有参考图
curl http://localhost:18001/api/characters/<character_id>
# 应该有 referenceImageObjectKey 字段

# 4. 查看详细日志
docker compose logs worker --tail=500 | grep -A 10 -B 10 "ref2va"

# 5. 重新运行测试
pytest backend/tests/test_h3_cascade.py -v
```
