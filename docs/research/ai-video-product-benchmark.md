# AI 视频与口型产品机制基准

> 用途：为 ComicFlow 的动态中文竖屏漫剧方案提供产品机制参考。本文优先引用官方文档、官方产品页和官方代码仓库；商业产品的模型质量、免费额度和中国区可用性不在本文中作承诺。
>
> 调研日期：2026-08-31

## 结论摘要

现有成熟产品通常把“画面生成”和“声音生成”拆成多个可独立重做的轨道，而不是一次请求直接生成完整成片：

1. **镜头生成**以短片段任务为单位，输入提示词、参考图/视频、比例、时长等参数，异步返回任务状态和视频资产。Runway 的开发文档展示了 image-to-video 任务、比例、时长、轮询/等待任务输出的流程。[1]
2. **角色动作**通过参考图、动作提示、视频到视频或角色驱动实现；产品界面通常允许重做单个镜头，而不是重做整部作品。Runway API 将 image-to-video 与 video-to-video 分开；Kling 官方创作入口强调文本/图片到视频和多模态参考输入。[1][2]
3. **口型同步**通常以“已有音频 + 角色/头像视频”为输入，输出一个新的说话视频，而不是让 TTS 同时决定画面动作。HeyGen 的 API 将视频生成、角色/Avatar、音频与字幕配置作为结构化参数；开源 MuseTalk/Wav2Lip 也采用音频驱动口部区域的独立处理。[3][5][6]
4. **声音**是独立资产：TTS 生成音频及时间信息，字幕、口型、动作再对齐到统一时间轴。这样可以只替换配音，不重新生成画面。
5. **ComicFlow 应采用“镜头资产 + 音频资产 + 时间轴 + 合成”四层模型**。动态视频模型不可用时，才回退到局部 2D 驱动；不能把静态图片作为默认产品形态。

## 产品机制对比

| 产品/方案 | 画面生成单位 | 动作与角色控制 | 声音/口型 | 时间轴与交付 | 对 ComicFlow 的启示 |
|---|---|---|---|---|---|
| Runway Dev API | 异步 generation task；image-to-video、text-to-image、video-to-video 等独立端点 | 通过提示词、输入图片/视频和模型参数控制镜头；单任务有比例与时长字段 | API 文档重点在视频生成，口型需另接角色/音频方案 | task 完成后返回输出 URL；失败返回 task details | 生产接口要以 Job/Task 为中心，镜头可独立重生成，输出资产持久化 |
| Kling/可灵 | 产品侧提供文生视频、图生视频、多模态/参考输入等创作流程 | 以首帧/参考素材和运动描述控制主体、镜头和风格；具体 API 能力需按可灵账户文档实测 | 产品宣传包含音频/口型相关能力，但公开技术契约和地域可用性需核验 | 通常是短片段生成后进入剪辑/拼接 | 将“参考图、动作描述、镜头运动、时长”作为结构化分镜字段，不把一整段剧本直接交给模型 |
| HeyGen | 结构化视频任务，Avatar/scene/audio/caption 等配置组合成视频 | 角色由 Avatar/数字人资产驱动；动作、镜头和布局由场景参数约束 | 以脚本或音频驱动角色说话，并提供字幕配置；口型属于角色视频生成链路 | API 创建任务后异步查询视频状态和下载地址 | 口型必须以音频资产为事实来源；台词、说话人、字幕和口型共享同一段落 ID |
| Adobe Character Animator | 角色 puppet + 摄像头/音频实时驱动，随后进入 Adobe 时间轴 | 通过头部转动、眨眼、触发器、身体/手势行为驱动；动作是可编辑行为而非一次性重绘 | Lip Sync 行为根据麦克风/音频自动分析口型；可手动修正口型 | 行为轨道进入时间轴，支持逐帧调整与导出 | ComicFlow 应提供可编辑的动作/口型轨道和人工覆盖，不只显示模型黑盒结果 |
| MuseTalk（开源） | 已有人物视频/图像区域 | 主要驱动嘴部区域，保持其余脸部和身体稳定 | 音频驱动 lip-sync；适合作为独立口型阶段 | 输入音频与视频后输出同步视频片段 | 优云可部署路线可先采用独立口型服务；必须记录模型版本、帧率和音频采样率 |
| Wav2Lip（开源） | 已有人脸视频 | 不负责全身动作，只修改口部区域 | 音频驱动嘴型同步；适合短片段和基线评测 | 生成新视频文件，后续仍需合成 | 适合作为口型基线/回退，不应误当作完整动作生成模型 |
| SadTalker（开源） | 单张人像 + 音频 | 音频驱动头部姿态和表情运动 | 同时完成音频驱动口型与头部运动 | 输出说话头像视频 | 可用于近景对白镜头；需限制画风漂移，并与镜头合成隔离 |

## 1. Runway：异步镜头任务范式

官方开发文档把视频生成建模为任务：示例使用 `imageToVideo.create`，传入模型、提示词、比例和时长，再等待任务输出；文档同时列出 image-to-video、video-to-video 等能力。[1]

**可借鉴机制**

- 每个镜头一个 `GenerationJob`，有 `queued/running/succeeded/failed` 状态。
- 生成参数保存在镜头版本中：`model`、`prompt`、`referenceAssets`、`ratio`、`duration`。
- 任务完成返回对象存储地址，前端显示缩略图、时长、模型版本和重试按钮。
- 失败不能覆盖上一版成功资产；重试创建新 job 并保留错误原因。

**限制**

Runway 是商业 API，不能作为 ComicFlow 的生产默认模型；这里仅借鉴任务和参数设计。ComicFlow 实际实现需将同样的契约接到优云可部署免费模型和 Mock Adapter。

## 2. Kling/可灵：参考素材 + 运动描述

可灵官方产品入口将视频创作分成文生视频、图生视频等模式，并以图片/视频参考和运动描述控制生成结果。[2] 公开页面的能力、地区、额度和 API 细节可能随版本变化，不能直接当作 ComicFlow 的固定依赖。

**可借鉴机制**

- 分镜表至少要有：首帧/角色参考、场景参考、动作描述、镜头运动、目标时长、画幅比例。
- “动作描述”与“台词”分栏，避免把口语内容误当成视觉动作。
- 允许同一角色卡被多个镜头引用，保证角色参考一致性。
- 生成结果要有“接受/重做/局部修订”三种操作，而不是只有生成按钮。

## 3. HeyGen：角色、脚本、音频和字幕的结构化组合

HeyGen 的公开 API 参考以“创建视频”作为结构化请求，视频由角色/Avatar、脚本或音频、场景布局、字幕等参数组成；创建后再查询任务状态和视频输出。[3] 文档在部分地区可能需要登录，因此具体字段应以接入时版本为准。

**可借鉴机制**

- 说话段落使用稳定的 `dialogueSegmentId`，绑定 `speakerId`、文本、音频、字幕和口型轨道。
- TTS 和口型必须解耦：替换音色时，只重新生成音频和口型，不重做背景与动作。
- 预览界面应能切换“画面/声音/字幕”轨道，显示实际时长而非只显示文案。
- 视频任务异步执行，前端必须支持断点刷新和失败重试。

## 4. Adobe Character Animator：可编辑行为和口型轨道

Adobe 官方文档描述了基于 puppet 的角色动画：头部、眨眼、触发器和 Lip Sync 等行为由摄像头或音频驱动，并进入可编辑时间轴。[4]

**可借鉴机制**

- 角色资产不仅是一张图，还应包含口型集合、表情集合、动作锚点和层级信息。
- 自动口型生成后允许人工选择某个时间区间的口型，解决中文同音、噪声和情绪夸张问题。
- 动作轨道要有关键帧和强度参数；生成模型只提供候选动作，编辑器负责最终裁决。

## 5. 开源口型与说话头像方案

### Wav2Lip

Wav2Lip 官方仓库提供音频驱动唇形同步推理代码，核心输入是视频和音频，输出同步后的视频。[5] 它主要改变口部区域，不负责全身动作和镜头设计。

### MuseTalk

MuseTalk 官方仓库定位为实时/高质量音频驱动唇形同步，支持对人脸区域进行音频驱动生成。[6] 其适合作为独立的 `LipSyncProvider`，输入应包含人物视频片段、音频、帧率和人脸区域信息。

### SadTalker

SadTalker 官方仓库定位为“单张肖像 + 音频 → 说话头像视频”，同时驱动头部姿态和表情。[7] 它更适合近景独白/对白镜头，不适合作为所有远景动作镜头的通用动画器。

**开源方案共同注意事项**

- 许可证、商用限制、模型权重下载方式必须在优云部署前单独审核。
- 需要测量中文普通话、多说话人、情绪语气、侧脸和遮挡等场景，不应只看英文正脸样例。
- GPU 显存、推理速度、分辨率和批量并发决定实际成本；“开源/免费”不等于基础设施免费。

## ComicFlow 应采用的目标架构

```text
剧本/分镜
  ├─ ShotSpec：角色、场景、动作、镜头、台词
  ├─ VisualJob：优云动态视频模型生成镜头片段
  ├─ TTSJob：生成单说话段落音频 + 时长/词级时间信息
  ├─ LipSyncJob：用音频驱动口型/头部动作
  ├─ SubtitleTrack：由台词和时间信息生成字幕
  └─ ComposeJob：按统一时间轴合成 9:16 MP4
```

### 推荐的时间轴数据

```json
{
  "shotId": "shot-03",
  "durationMs": 6200,
  "visualAssetId": "asset-video-03-v2",
  "dialogue": [{
    "segmentId": "dlg-03-01",
    "speakerId": "char-linmo",
    "text": "你终于来了。",
    "audioAssetId": "audio-dlg-03-01-v1",
    "startMs": 1800,
    "endMs": 4300,
    "lipSyncAssetId": "lipsync-03-01-v1"
  }],
  "actionTrack": [{"type": "turn_head", "startMs": 900, "endMs": 1700, "intensity": 0.7}],
  "cameraTrack": [{"type": "push_in", "startMs": 0, "endMs": 6200, "from": 1.0, "to": 1.08}],
  "subtitleTrackId": "sub-03-v1"
}
```

### 生成顺序

1. 先锁定角色卡和分镜动作，再生成动态画面候选。
2. 画面通过审核后生成 TTS；TTS 返回音频、总时长和词/音素时间信息。
3. 仅对有对白的角色调用口型模型；无对白镜头不产生无意义的 lip-sync 任务。
4. 将视觉片段、口型片段、动作、字幕、音乐和音效对齐到同一时间轴。
5. 合成低清预览，审核通过后再生成 1080×1920 导出版本。

### 质量门禁

- 口型：对白开始/结束误差 ≤ 120 ms；正脸对白可接受率、侧脸降级率分别统计。
- 动作：镜头内动作必须落在分镜定义区间；不得因重新配音改变动作时间轴。
- 角色：局部口型生成不得改变角色身份、发型、服装和画风。
- 音频：检测削波、静音、爆音、背景音乐压对白等问题。
- 视频：检查 9:16、帧率、音画总时长、字幕安全区和首尾黑帧。

## 对当前前端/PRD 的直接修改建议

1. “声音与字幕”阶段改成“声音、口型与时间轴”，显示 TTS、口型、字幕三条可编辑轨道。
2. “动态镜头”阶段增加动作轨道和说话人标记；台词编辑不应藏在生成按钮后。
3. 每个镜头提供“只重做画面”“只重做配音”“只重做口型”“重做整镜头”四个动作。
4. 预览必须能拖动时间指针，点击对白段落时高亮当前说话角色嘴部和字幕。
5. 模型策略页显示各 Provider 的输入/输出能力、显存需求、失败回退和预计耗时；优云免费模型是生产默认，Mock 只作为开发/异常降级。
