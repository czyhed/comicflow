## 重要发现：MiniMax H3 原生支持角色一致性

根据 MiniMax H3 官方文档，H3 模型已经**原生支持多角色参考图**和**角色一致性保持**，无需三面图方案。

### H3 的关键能力

#### 1. 多模态参考能力
- **全能参考入口**：≤ 9 张图片，可同时传入多个角色的参考图
- **角色参考方式**：使用 `<Subject N>` 标签锁定角色外观（脸、发型、服装、体型）
- **跨镜头一致性**：同一 `<Subject N>` 在多个镜头中自动保持外观一致
- **动作参考**：可传入参考视频，提取动作并迁移到目标角色

#### 2. 首尾帧级联（i2v）
- **首帧模式（I2VA）**：从一张图片开始生成视频
- **首尾帧模式（FL2VA）**：给定首帧和尾帧，H3 自动插值中间过程
- **尾帧模式（L2VA）**：给定尾帧，H3 反推开头并收敛到尾帧
- **分辨率支持**：768p（短边768px）或 1440p（短边1440px，官方推荐）

#### 3. Prompt 结构化
H3 使用结构化 Prompt，包含：
- `subject_definitions`：定义角色、场景、物体的参考素材
- `detailed_description`：按时间线描述画面、动作、镜头、台词
- `overall_soundscape`：环境声和物理声音
- `non_diegetic_music`：背景配乐

## 任务 3：场景背景融合技术调研

### 背景
- **需求**：为每个场景生成背景图（如"雨夜的车站"），让角色在这个背景前活动
- **目标**：同一场景内的多个镜头，背景保持一致（不突变）
- **当前问题**：如果每个镜头独立生成视频，背景会完全不同

### 需要调研的方案

#### 3.1 i2v 的背景控制方法

**方案 A：首帧作为背景**
- 流程：生成背景图 → 作为 i2v 的首帧输入 → 角色在背景前动作
- 疑问：
  - Wan3.0 / MiniMax H3 的 i2v 是否支持这种用法？
  - 如何保证角色出现在前景、背景不变形？

**方案 B：ControlNet Depth Map**
- 流程：生成背景图 → 提取深度图 → i2v 时用深度图约束背景结构
- 疑问：
  - Wan3.0 / MiniMax H3 是否支持 ControlNet？
  - 深度图能否保证背景完全一致？

**方案 C：视频抠图 + 背景合成**
- 流程：
  1. 生成纯色背景的角色动作视频（绿幕效果）
  2. 用视频抠图模型（rembg / MODNet）提取前景
  3. 合成到背景图上
- 疑问：
  - 抠图质量如何？边缘是否自然？
  - 需要额外的抠图模型部署吗？

**方案 D：提示词工程**
- 流程：在提示词中详细描述背景（"in front of rainy train station at night"）
- 疑问：
  - 这种方法能保证背景一致性吗？
  - 还是每个镜头的背景都会略有不同？

#### 3.2 关键问题

1. **哪种方案的背景一致性最好？**
   - 同一场景的 3 个镜头，背景能保持 80% 以上相似度吗？

2. **技术可行性**
   - Wan3.0 / MiniMax H3 是否原生支持背景控制？
   - 如果不支持，后处理方案的工程复杂度有多高？

3. **推荐方案**

#### 4.2 完整工作流（伪代码）
```
1. 用户输入故事 → 生成剧本（已实现）
2. 剧本确认后 → 资产生成阶段：
   a. 角色资产：
      - 为每个角色生成标准正面照（wanx-t2i）

   b. 场景资产：
      - 为每个场景生成背景图（wanx-t2i）
      - 存储到 MinIO
3. 视频生成阶段（按镜头顺序）：
   for each shot:
      if 首镜头:
          input = 场景背景图 + 角色三面图 + 动作提示词
          call i2v_api(input) → video
      else:
          prev_last_frame = extract_last_frame(prev_video)
          input = prev_last_frame + 角色三面图 + 动作提示词
          call i2v_api(input) → video
4. 合成完整视频（ffmpeg，已实现）
```

- 是否需要重新开始首帧级联（镜头 4 不用镜头 3 的尾帧）？

**疑问 4**：角色在不同场景如何保持一致？
