## 本批修复

确认剧本原来在配置了图片能力时，会为没有背景图的场景直接调用图片供应商。用户点击“确认剧本并生成分镜”可能隐式消耗图片额度。

在公开Pipeline入口补回归，原代码出现1失败/4通过，记录到两次图片调用；删除`confirm_script`中的自动场景生图后5通过。确认只校验角色卡并保存确认状态；已有“准备场景参考图（图片API，可能计费）”仍负责显式生成，已存在图片复用。原风格测试改为验证这个显式入口，保留风格快照断言。聚焦17项通过。

涉及业务文件仅`backend/src/comicflow/production/pipeline.py`及两个回归测试。没有改提示词、Skill、参考模式或生成分辨率规则，也没有增加生产接口/数据表。新测试配置与脚本不进入生产部署。

## 贯穿验证

测试入口为`127.0.0.1:4184`，项目为`comicflow-verify-flow`临时Compose。API、Worker和PostgreSQL/Redis/MinIO只连接Docker内部网络；仅固定路由的测试Nginx另接浏览器入口网络。浏览器拦截仅阻断非测试域名，不替换任何业务API返回。

复用已有镜像和环境清理函数，在临时库迁移到0004。每次启动先清除供应商与代理环境变量，只设置假Key和回环假供应商地址。测试通过公开HTTP创建项目/配置/开发登录，不直写业务表或伪造项目完成状态。Celery为独立进程，outbox由测试派发循环处理，未启业务Beat。

| 环节 | 实际执行与断言 |
| --- | --- |
| API管理 | 同一假连接绑定文本、文生图、图生图、H3；保存重读和重启后绑定相同 |
| 剧本 | 导入故事，浏览器点击拆分；实际Chat Adapter请求假供应商，保存两场景六个5秒镜头与规划Skill来源 |
| 角色 | 自动识别林青/陈明，浏览器补设定；确认剧本不产生图片请求 |
| 场景 | 浏览器显式生成两个场景，各一次请求 |
| 主图/整板 | 两角色各一次主图、一次整板；分别确认；比较图片字节证明整板请求包含对应确认主图，候选不冒充已确认板 |
| 视频 | 六次真实H3 Adapter请求发到假HTTP服务；均768P、5秒；实际Prompt与准备单一致；重复操作ID返回同一作业 |
| 素材 | 第一镜1人物板+当前场景；第二/三镜2人物板+前镜尾帧+当前场景；第四镜换场为2人物板+新场景，无旧尾帧；第五/六镜恢复同场接续 |
| 参考证据 | 实际请求中解码图片，校验人物板与场景字节；尾帧清单ID/来源与上一已采用资产匹配。每角色仅一张板，未重复附主图和分视角 |
| 恢复 | 第三镜首次结果下载503；页面“继续查询/保存已有任务”恢复原任务，六镜总提交仍6次 |
| 采用门禁 | 每镜先候选、播放地址存在再采用；最后一镜未采用时合成返回ASSETS_INCOMPLETE，缺失s6；采用后合成成功 |
| 合成导出 | 真正FFmpeg处理六段本地运动测试片，H3原声，不生成TTS；页面预览能够播放，签名HTTP下载MP4/封面/SRT |
| 重启 | 完成后重启隔离API与Worker，浏览器刷新仍显示导出就绪，确认板/六段当前资产/模型绑定均保留 |

最终成功轮假供应商生成调用：文本1、图片6（场景2+主图2+整板2）、视频6；真实文本/图片/视频调用全部0。开发测试中的几轮脚本调试也只访问假供应商。图片假HTTP返回本地色块图，视频返回FFmpeg测试片，不能据此判断模型理解能力。

H3这条路径使用现有中文Context-IR编译，视频作业本地文本扩写0次；不是每镜调用外部Skill文本模型。剧本/图片仍沿用现有Skill适配。供应商内部优化是否收费及真实效果不在模拟结论内。

## 媒体验证结果

实际下载MP4经ffprobe检查：30.022秒，1080×1920，30fps，H.264/AAC，偏差0.022秒小于1帧。六个时间点的色标证明镜头顺序正确，每段两帧不同证明存在画面运动；六段独立测试音调440/550/660/770/880/990Hz均按顺序保留。封面可解码且为1080×1920；SRT六段、结束时间00:00:30,000。

这里的1080×1920是现有合成器输出规格，不是向H3请求1080P/2K。六次H3请求均为768P；测试源片为360×640，放大合成不能增加真实细节。真实供应商输出时长和画质仍需人工验收。
