# 故事/剧本流式输出与HTTP生图兼容

2026-09-24，用户要求实时输出、排查拆分多次调用和修复服务器`crypto.randomUUID`报错。本批只本地源码和离线验证，不调用真实模型、不部署。

## 契约与决策

- 故事生成和拆分预览沿用既有POST地址，浏览器以Accept: text/event-stream请求逐段进展和最终结果；无该Header保留JSON响应。一次点击仍为一次生成POST，不用轮询POST驱动进度。
- 标准Chat Completions使用供应商SSE增量；兼容模板保持模型、预算、消息和路径，标准响应结构可流式。明确关闭stream或非标准响应映射时只做原有一次请求，界面如实显示等待，不伪造逐字输出。忽略推理字段，不把模型内部思考展示为剧本。
- 部分内容仅作预览；最终完整结果仍在本地校验，剧本仍需明确确认才保存。失败/截断保留原稿，不因流式失败再发非流式请求。断线不自动重试付费POST，故事已开始时服务端继续完成原请求；客户端提示核对已保存结果。
- 去掉故事流式失败后的重新生成及结构化故事修复请求，完整正文的既有本地提取兼容仍保留。普通剧本拆分已有单次请求限制，保留本地契约检查，不把它误称为多轮模型审查。
- HTTP浏览器可能没有randomUUID；统一操作ID工具优先原生UUID，其次getRandomValues生成UUIDv4。生图继续保留未知响应时的同一operationId，不因兼容修复增加调用。图片、视频和合成共用该工具。
- UI展示真实内容、已等待秒数及等待/输出/本地校验状态，移除定时轮换的虚构阶段。保持未完成内容与可编辑/可确认的最终结果分开。

## 复现与验收计划

浏览器禁用randomUUID复现原生图按钮错误和0次提交；真实Adapter+MockTransport核对流式POST一次、模板预算保留、截断不保存、确认零模型调用；覆盖中途可见内容、流中错误及无终态断线。完成后记录结果与部署边界。

## 查明的原因

1. HTTP IP访问不是浏览器安全上下文，`crypto.randomUUID`不可用。角色主图、图生图整板和文字整板的同一提交函数直接调用该API；模拟禁用它后，页面精确出现用户报错且提交次数为0。改用getRandomValues构造UUIDv4后，同一浏览器测试三种用途均能提交。合成入口的相同缺口一并修复，视频也统一采用相同工具。
2. 原故事Provider已有流式方法，但模型库自定义模板的`TemplateTextProvider`覆盖了它，实际上整段返回。剧本预览/拆分原来只有JSON响应，前端剧本页没有实时内容。创建页还每900ms循环换“识别/校验”等文案，这不是实际多轮审核记录。
3. 普通拆分的`_complete_json(stage='script_split')`原已强制0次重试；场景/镜头规范化、中文/时长/引用校验和连续性规则均为本地函数。确认预览调用PUT保存已有内容，不再次生成。真正额外付费路径在故事：无效流式JSON会重新调用非流式生成，后者也可能再发一次修复请求。本批删除这两处自动重发；完整正文的本地解析兼容保留。

| 当前主要操作 | 文本生成请求 | 审核/校验 |
| --- | --- | --- |
| 故事生成 | 一次；失败不自动修复重发 | 沿用原有一次输入审核（若配置Provider），不为提速移除审核 |
| 拆分预览 | 一次；超时/截断不自动重试 | 只做本地结果契约与连续性处理，无模型二审 |
| 确认预览 | 零次 | 本地版本/结构校验并保存 |

这是源码追踪与离线HTTP调用计数结果；没有读取本次生产供应商账单/请求日志，不据此证明用户某一次历史账单只有一笔，也不判断供应商内部是否有推理或自审。

## 实现与行为

- `api/text_stream.py`复用原POST，以独立请求上下文回传phase/delta/result/error；每10秒心跳、禁用代理缓冲。断开观察连接不会取消并重发已开始的生成；不把部分内容保存成剧本。浏览器不会自动重新提交生成POST。
- `providers/text_progress.py`仅传递本次请求观察回调，模型/项目状态仍由原服务管理。`bailian_text.py`和模板适配器支持标准SSE、忽略推理字段；显式stream=false或自定义响应路径保持非流式。供应商忽略stream而返回JSON时消费同一响应，不另发请求探测。
- 标准delta.content中的重复词仍保留，不把正常重复文本误当累计帧去重；原累计帧兼容路径继续适用于旧Provider。
- `textStream.ts`增量解码跨网络分块的UTF-8/SSE，终态错误复用已有错误说明；没有result/error终态的断线明确报错。旧服务器返回JSON仍可读取，不触发第二次POST。
- 创建页的故事/导入内容以及剧本页的拆分/重新拆分均展示实时可读文字与等待秒数。隐藏JSON信封和推理字段，完成前不能编辑或确认；本次没有恢复已移除的逐步确认创作模式。
- 图片未知响应时仍使用原operationId，失败后不换ID偷偷再生成。无需更换模型Key或仙宫云设置。

## 完成验证

- 先红后绿：HTTP浏览器按钮原错误/零请求；新流式API的4种组合原无SSE；无效故事原2次请求。修复后对应测试通过。
- 完整后端离线949通过、3条件跳过（2项外部脱敏夹具、1项Docker冒烟）。运行器隔离业务环境并禁止外联socket。
- 前端82项Playwright通过、45项Node测试通过，包含真实本机HTTP流在终态前显示内容、截断保留原故事、单次POST及三种HTTP生图模式。截图检查通过，390px无横向溢出。
- 生产build通过、Ruff通过、Mypy检查96源文件通过。没有真实模型请求或生产数据写入，没有重新部署/重启服务器。
- 最后只读核对本机与服务器模型库：story/script均为doubao-chat、标准choices[0].message.content响应映射，请求模板没有显式stream=false。新代码会在流式调用中补stream=true并保留其他配置，不需要用户重填Key或修改持久JSON；仅核对配置兼容性，未实测上游流式生成。
