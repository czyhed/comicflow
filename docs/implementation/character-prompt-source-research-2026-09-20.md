## 1. 项目边界与证据口径

已读取 `docs/PROJECT_ENGINEERING_RULES.md`、`CONTEXT.md`、任务书 v2 `docs/implementation/quality-and-modularity-taskbook-2026-09-19.md`（重点第6、7节），以及 ADR 0004/0006、角色提示词助手和角色三视图的既有 spec。旧 spec 描述历史行为；本报告按任务书 v2 的角色用途与整板方向给建议，不改写任务书。

- 主参考图用于确认人物外貌、服装和项目风格；后续整板以已确认主图为身份依据。
- 新整板是**一次图生图生成的一张正面／侧面／背面候选板**，不是三次生成再拼接。主图与整板分别确认；本报告不增加自动特写、自动高清化或多候选竞赛。
- 润色主图提示词只输出 `referenceImagePrompt` 草稿，不借“质感升级”改写角色年龄、脸型、服装、性格。已有满意主图应复用。
- `image-2.5` 是本项目可能使用的配置名称／代理别名；本报告没有证据将其对应到任何特定官方模型。供应商案例不证明当前 Adapter 支持同样能力。

本文区分三类内容：**来源事实**是实际取得的原文或图像；**项目建议**是本次归纳与取舍；**未验证**指未在 ComicFlow 真实模型和下游视频中检验。官方展示是精选案例，不能据此推导成功率、一次生成的稳定性或跨供应商质量保证。

## 2. 供应商一手来源：实际读到了什么

### S1：Black Forest Labs，Building a Good Prompt

原文：[官方指南](https://docs.bfl.ai/guides/prompting_unified_building.md)。实际取得完整公开 Markdown；读取了提示词及配图链接，配图像素加载未成功，以下不作视觉效果断言。

短引文：**“Start short. Add only what changes the image.”** 文档说明模板不是每次必须填满的检查表，并明确提示不要堆叠通用质量词。其红发女性示例从主体逐步加入街道、时装摄影、85mm、柔和夕阳光，再加入琥珀／炭灰配色、颗粒与风吹头发。

**用途判断：**这是人物摄影／时尚构图示例，不是标准身份板。可以学习“主体→媒介→光线→配色”的具体化；街道、风吹头发、颗粒和背景灯光不应自动进入 ComicFlow 主参考图。文档也提醒不同模型不一定同样理解相同措辞。

### S2：Black Forest Labs，Style, Aesthetics & Text；Technical Parameters

原文：[风格与光线](https://docs.bfl.ai/guides/prompting_unified_style.md)、[比例与否定表达](https://docs.bfl.ai/guides/prompting_unified_technical.md)。实际取得完整公开正文；未逐张看见图像像素。

前者把光线拆为来源、软硬、方向、色温及与表面的交互；短引文：**“Describe it like a photographer would”**。还分别列出摄影与插画表现方式。后者写明 **“Most FLUX models do not support negative prompts.”**，建议用想看到的正向画面替代长串否定词，如清楚、无遮挡的眼睛；比例应与构图意图匹配。

**用途判断：**可迁移的是具体光线和媒介词汇、正向表达、比例与构图一致。伦勃朗光、半脸明暗分割、霓虹光都只是可选示例，不是身份参考图默认配方；“FLUX 多数模型不支持负向提示”也不能扩展成所有供应商都不支持。

### S3：Black Forest Labs，Character & Style Consistency

原文：[官方角色一致性案例](https://docs.bfl.ai/guides/usecases_editing_character_consistency.md)。实际读取到原始提示词、输入／输出配图地址与图注，未看到图像像素。

案例包括移除脸前物体、把同一人物移到 Freiburg 街道、再改为雪景；另一个双图合成案例明确指定：人物来自 Image 2，街景及风格来自 Image 1。短引文：**“Apply the style of Image 1 to them as well”**。

**用途判断：**原案例主要用于编辑、剧情场景和时装系列；对本项目有用的是**明确每张图供给身份、环境还是风格**，不是照搬雪景或时装系列。文档所述一致性依赖图像参考编辑，不是单靠“同一个人”四个字就保证一致。

### S4：Google Gemini 官方 Cookbook

原文：[Book illustration](https://github.com/google-gemini/cookbook/blob/main/examples/Book_illustration.ipynb)、[Nano Banana quickstart](https://github.com/google-gemini/cookbook/blob/main/quickstarts/Get_Started_Nano_Banana.ipynb)。通过公开 GitHub Contents API 读取 notebook 的文字和提示词，**没有运行 notebook，也没有检查其生成图像输出**。

书籍插图教程先定义风格，再生成主要角色肖像，再生成章节插图；原文小节分别为 **“Define a style”**、**“Generate portraits of the main characters”**、**“Illustrate the chapters of the book”**。角色描述取自书中信息，章节提示词继续复用人物描述。Quickstart 的猫示例先指定左右眼颜色、脸部红斑、黑粉色鼻子，再要求侧视图；另有 Pop Art 示例写明粗黑轮廓和有限的平涂色板。

**用途判断：**角色肖像与章节插图的用途分离直接相关；猫不是人物案例，但展示了可辨识视觉特征的明确描述。Pop Art 只能提供2D风格描述方式，不能据此把所有2D项目都改成粗线条。教程的多轮交互、文本调用、字数下限及 API 参数属于其具体演示，**不移植成 ComicFlow 新的额外调用或最低长度要求**。

### S5：字节 Seedream 4.0 官方展示——换视角并保持人物

原文及配图入口：[Seedream 4.0 官网](https://seed.bytedance.com/en/seedream4_0)，定位 **Batch Input & Output／多图组合**。实际读取公开页面中的案例说明，并成功查看其输入图和输出拼图像素。

中文原始提示词包含：**“不要改变女孩的外貌和装扮。”** 完整意图是依据参考图分别输出俯视、仰视、背面等视角；官方英文和中文对视角的表述不完全一致，因此不把该句整体当作精确机位规范。

实际所见：输入是一位戴棕色宽檐帽、编辫子、系颈巾的人物，位于峡谷环境。输出展示三格：明显俯拍、由下方看人物及岩石拱洞、人物背面；帽子、辫子、颈巾、服装色系在展示图中延续。**这不是正面／侧面／背面的中性身份板**，也不证明脸部在各角度达到可量化的一致性。

特别重要：官网明确写 **“Examples below show combined results.”**，中文为“官网示例为多图拼接效果”。因此它能支持“改变视角、指定保留外貌服装”的思路，**不能作为一次生成一张三视图整板已获官方验证的证据**。

官网链接的 [中文提示指南](https://bytedance.larkoffice.com/wiki/CP77wUHKAihPqKkWogccbr63nrd) 和 [英文提示指南](https://bytedance.larkoffice.com/docx/PBvldM6Xlo5OHKxsRNVcyAq4nFe) 本次均发生重定向循环，未取得正文。[BytePlus 的 Seedream 4.0–4.5 prompt guide](https://docs.byteplus.com/en/docs/ModelArk/1829186) 只取得标题、导航和更新时间，未取得指南正文，不能引用其具体规则。

## 4. 七条可采用原则：证据与项目建议分开

### 1）先声明资产用途，再给视觉细节

**来源事实：**S4 将角色肖像与章节插图分开；C1 #11 将视角、表情、动作等作为不同设计任务列出。

**项目建议：**主图开头写“用于后续人物一致性的单人角色主参考图”，整板开头写“依据输入主图制作同一人物的三视图”。清洁背景、完整轮廓和清晰五官是主图的优先目标。姿态可以放松自然，但剧情动作、场景叙事、海报文字不成为默认内容。全身是为任务4补足服装与轮廓的建议，不是供应商保证最优的硬规则；已有合格主图不因这条建议被强制重画。

### 2）锁住少量可核对的身份锚点，不以“更美”改脸

**来源事实：**S3 明确依靠图像参考延续身份；S5 在改变视角时明确保留外貌与装扮；S4 示例明确颜色、斑纹等可辨特征。

**项目建议：**优先保留角色卡中的年龄感、脸型、眉眼、发型轮廓、体型、服装结构及已有标志配饰。润色只使这些事实更容易看见，不自行增添痣、伤疤、首饰或职业装。整板写明保持输入人物身份与服装，允许视角变化；不要同时要求“始终看镜头”和“背面”。

### 3）用一套明确光线建立体积，保留面部信息

**来源事实：**S2 拆解光源、软硬、方向、色温、材质交互；C1 #26 把打光作为独立编辑目标。

**项目建议：**写实主图可采用“大面积柔光从前侧上方照亮，另一侧轻柔补光，脸部细节清楚，脚下有柔和接触阴影”。方向性塑造体积，补光保住身份信息。不要把均匀无阴影、半脸深黑、强逆光、正面硬闪同时当作质感要求。2D用明确明暗块关系；3D用柔和主光和接触阴影，按媒介改写。

### 4）材质写可见特征，并限定作用部位

**来源事实：**C1 #2 具体描述丝绒与丝绸；S2 要求描述光与表面怎样交互。C1 #1 表明“手办、塑料底座”等词属于商品化表现。

**项目建议：**把“高级材质”替换成“外套羊毛细绒与自然垂坠”“皮带柔和光泽”“金属扣小面积反光”等角色服装已有材质的可见表现。写实皮肤强调自然纹理与肤色层次；2D用线条、色块与褶皱区分布料；3D用不同表面粗糙度区分皮肤、布料、金属。材质必须服从设定，不能为展示效果把普通棉衣变成丝绸礼服。

### 5）每次选择一个主导媒介，与项目风格匹配

**来源事实：**S1/S2 分别描述摄影、插画等媒介，要求组合自洽；S4 先固定风格再产生角色与章节图；C1 #10 将线稿、上色分开表达。

**项目建议：**写实使用摄影式形体、肤质与织物；2D使用项目匹配的线稿、平涂／赛璐璐等明暗方式；3D使用建模轮廓、体积与材质响应。不把“照片级毛孔＋纯平面赛璐璐＋塑料手办”作为所有风格共用后缀。借鉴来源案例的描述维度即可，不要求复制某位作者或某家工作室风格。

### 6）构图服务身份读取；整板独立规定三个视角

**来源事实：**S2 提醒比例与构图意图匹配；C1 #11明确正面、侧面、背面；S5 虽展示三格，但它是多图拼接示例。

**项目建议：**主图采用自然透视，眼部可辨、轮廓完整、主要服装无遮挡；不要默认用广角畸变、极浅景深和大片裁切。整板按左正面／中侧面／右背面、同尺度、同脚底基线排列，人物间留空隙。只对正面要求看清双眼；侧面强调轮廓；背面强调后脑发型和服装背部。横向画布要从实际模型支持尺寸中选，并服从下游比例限制，不把提示词里的“4K／8K”视为真实请求规格。

### 7）删冲突与泛化形容词，留下能改变图像的指令

**来源事实：**S1 明说长提示不自动更好、模板不必填满；S2 建议正向描述可见结果。

**项目建议：**本地组装或文本润色按“角色事实→项目媒介→当前图片用途→少量光线材质细节”组织。每个维度选相容的一套描述，减少重复“高级、顶级、杰作、超精细”。冲突先判断意图再消解，不能无声删除用户要求。此处是组装审阅原则，不建议新建关键词打分器、复杂优先级引擎或自动付费纠错流程。

| 常见冲突／误用 | 建议处理 |

| 单人单幅／仅正面 ＋ 同一人物三视图 | 主图和整板分别组装；整板使用“三个视角的同一人物” |

## 5. 三个原创中文主参考图示例

以下均为本报告原创的演示角色和草稿，不是抄录来源提示词，也不是对现有项目角色的修改。用于说明同一方法怎样适应不同媒介；衣服材质、身体比例等必须替换为真实角色卡信息。没有生成样图，不能标记为“已验证高质量”。

### 写实：用克制的光线和材质建立质感

> 用于后续人物一致性的单人角色主参考图，写实摄影风格。林岚，30岁女性，长椭圆脸、平直眉、深棕眼睛，黑色齐肩短发，左侧头发别在耳后，身形修长。穿石墨灰羊毛短外套、米白棉衬衫、深灰直筒长裤和黑色皮革短靴。正面自然站立，双臂放松，双手和完整鞋履可见，平静表情，眼睛看向镜头。浅暖灰摄影棚背景，自然透视，全身轮廓与服装均清晰。大面积柔光从前侧上方照亮，另一侧轻柔补光；面部保留自然纹理和肤色层次，羊毛细绒、棉布褶皱与皮革柔和反光彼此可辨，脚下有轻柔接触阴影。色彩克制，重点呈现人物身份和服装。

**适用／边界：**适合写实主图；不是剧情剧照。没有混入胶片颗粒、戏剧性半脸阴影、照片时间戳或虚假相机参数。

### 2D：精度来自线条与色块，不来自毛孔

> 用于后续人物一致性的单人角色主参考图，精致2D动画设定画，干净线稿与赛璐璐上色。许棠，24岁女性，圆润下颌、微挑眉、琥珀色眼睛，深栗色短发在下颌处内扣，左耳戴一枚小银色圆耳钉，身形匀称。穿墨绿色短夹克、米白圆领上衣、深蓝直筒裤和白色低帮鞋。全身正面自然站立，双臂稍离躯干，表情平静，发型外轮廓和鞋履完整。浅灰背景，以墨绿、米白、深蓝构成稳定配色；外轮廓清晰，内侧线条克制。统一的左前上方光照用两级明暗色块概括体积，五官和服装结构清楚；用少量有方向的褶皱表现布料厚薄，小耳钉仅有简洁亮点。

**适用／边界：**适合相应2D项目，不适用于水彩、无描边绘本等其他2D风格的自动默认。耳钉是这个虚构示例的原始设定，不是推荐给所有角色增加饰物。

### 3D：区分皮肤、布料和金属的表面响应

> 用于后续人物一致性的单人角色主参考图，风格化3D动画角色，清晰简洁的建模轮廓和自然人体比例。周砚，32岁男性，方圆脸、浓直眉、深棕眼睛，黑色短发向右梳，肩背宽厚。穿海军蓝棉质工装外套、浅灰针织内搭、炭灰长裤和棕色皮靴，外套使用小型哑光金属扣。全身正面放松站立，双手可见，神情沉静，头顶与鞋底完整入画。浅灰无缝背景，柔和主光来自左前上方，右侧弱补光，脚底有自然接触阴影。皮肤以平滑但有层次的色调和克制高光表现，布料呈粗糙漫反射与自然厚度，针织纹理不过度抢眼，金属扣保留小面积反光，皮靴光泽柔和；整个角色从脸部到鞋履都保持清晰。

**适用／边界：**适合风格化3D角色主图；没有玩具包装、塑料底座或桌面场景。若项目原本采用Q版比例，沿用已有比例，不能套用此例的自然人体比例。

### 从主图到整板的用途转换

以上例子的“正面、看向镜头、单幅主图”只用于主图。整板请求应以实际上传的已确认主图为身份来源，保留对应媒介与材质描述，**替换**主图构图段为：一张横向角色板、从左到右正面／严格侧面／背面、等高全身、同脚底基线、间隔清楚、保持同一套服装发型与体型、统一简洁背景和可辨识照明。

这是任务4的项目设计建议，不是来源中的逐字模板。背面不可见的服装结构仍可能由模型补全；提示词不能证明补全符合角色设计，需人工检查。整板若丢脸、变衣服、视角错误或人物重叠，属于不合格候选，不通过额外强调“高级感”掩盖。
