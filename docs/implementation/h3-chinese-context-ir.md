# H3 中文提示词与优云 Context-IR

2026-09-16 已实现并更新本地 API。真实生成由用户亲自操作，尚未进行画质验收。

## 在页面切换

1. 打开 http://127.0.0.1:5173，刷新页面。
2. 右上角「模型 API」→「视频 API」→编辑当前使用的配置。
3. 「H3 提示词处理」选择「中文 + 优云提示词优化」，分辨率选择「768P（默认低成本档）」，保存视频配置。当前正式配置已这样设置。
4. 在画面页选择一个镜头，手动生成或重新生成。不要先批量重生成整片。现有重生成成功后会替换当前有效视频，不是候选确认模式。
5. 对照人物、动作是否完整、对白、空间关系和画面质感。若不满意，可在相同位置切回「本地英文 Skill 扩写」。

保存与切换不调用模型。点击生成仍会产生供应商调用，平台优化的费用按供应商账户计费；本功能不宣称免费。

## 两条路径

| 配置 | 提交前 | 提交给优云 |
| --- | --- | --- |
| `local-skill`（代码默认） | 调用当前文本模型执行原 H3 Skill，英文正文校验、原文对白注入 | 英文描述与原语言对白；不启用平台二次优化 |
| `context-ir` | 本地整理已保存中文镜头、角色外貌/服装、场景、动作起中终状态、准确对白、声音和真实参考编号，不调用文本模型 | 中文创作输入、原有图片、`use_context_ir=true` |

新路径不是“执行了中文版本的官方 Skill”。它将优化交给优云，未传 `skill_id`，未下载仙宫云 Skill。供应商最终优化后的 Prompt 未公开返回；资产保存的 `h3Prompt` 是提交的中文输入，不是平台优化后的输出。`promptExecution.mode=context-ir`、`localTextCall=false`，不得伪造本地 Skill 执行记录。

整理时不翻译历史英文草稿，不改写对白，不使用旧 `h3Prompt`；输入内容来自当前已保存剧本。`visualStyle`、动作状态、运镜等中文字段原样保留。图片标签与实际传图顺序一致；三视图板明确是同一个人的多个视角，不要求画面生成三个人。上一尾帧为普通参考时，描述不伪称严格首帧约束。

保留既有图片预检、4–15秒时长、参考/首尾帧互斥、9张图片限制、7000字符限制。超限/空镜头在提交前拒绝，不截断、不自动重试、不退回英文文本调用。切换扩写模式的提交幂等键不同，同一模式同一项目版本重复请求保持稳定。

## 中文提示词规则 V2

2026-09-16 已按用户提供的短视频模板完善并部署API，最终中文提交文本按以下顺序组织：

```text
【参考素材】实际图片编号、绑定角色和用途、哪些保持/哪些允许改变
【成片目标】实际秒数、画幅、镜头核心内容
【场景与风格】角色外观服装、地点时间、原有光线色调景深画风
【镜头与动作】原画面、景别、运镜、表演、动作节奏和最终状态
【台词】原说话人、语气、逐字对白/旁白和口型要求
【声音】原环境声/音效/配乐，静音与对白优先级
【限制】身份空间稳定、不新增剧情台词、不添加字幕水印、原稿正常切镜
```

只有完整起中终状态且原稿没有秒级时间安排时，才给20%/60%/20%的建议节奏，例如5秒为0–1/1–4/4–5秒，15秒为0–3/3–12/12–15秒。它不是测算得到的精准对白时间，也不是三次切镜；平台可按动作与台词微调，总时长不变。原稿已有时间描述时不再生成第二条时间轴；状态不完整则使用全段范围，只保留已知状态。顶层动作状态优先，空缺可从continuityPlan读取。

没有实际动作视频或音频输入时不添加虚构引用。用`<Picture N>`匹配真实图片顺序，不照搬网页的悬空`@资产名`。角色三视图板标为同一人物的多个视角。不会照抄模板中的固定画风、雨夜或主播台词。此模板是对原稿组织方式的改进，无法补救错误人设、模糊图片或原稿中自相矛盾的剧情。

本地示例：`.scratch/h3-chinese-context-ir/chinese-v2-example.txt`（推门进便利店，未调用模型）。`compilerVersion=2`参与context-ir幂等键，同版重试不变，升级不取旧版任务。
