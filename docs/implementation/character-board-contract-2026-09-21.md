## 文字整板补充（2026-09-21，用户授权实现）

- 新 purpose=text-board：已保存姓名/外观/服装 + 项目风格 + 本地 character-text-board Skill → image 用途绑定 → 一次图片请求 → referenceBoardCandidate → 用户明确确认 → H3 一个角色一张参考板。无主图也可用，无额外文本模型调用。
- 构图：左侧正面脸部特写，右侧正面/严格90°侧面/180°背面全身，一张横向设定板。使用外观/服装而非旧主图提示词，避免单人正面/竖版约束冲突；不保证沿用旧主图的脸。
- 与原 board 图生图分开选择，原入口与模型绑定保留。新板不带 sourceImageUrl/ObjectKey，来源检查记录外观/服装/风格，不虚构主图引用。
- 复用现有表、活动槽、租约、恢复与确认接口；未知作业依旧阻止所有同角色的新生图。图生图的配置尺寸门禁保留；文字整板有配置尺寸时校验，无尺寸参数的 Chat 协议通过提示词要求横版，并校验实际图片。不得偷偷添加供应商不支持的 size 或强制4K。
- 验收：模拟真实 Chat 图片协议，证明一次提交、无参考图、无编辑模型调用、无主图时可确认及传H3、来源变化拒绝、重复执行和未知防重、页面刷新/确认。全部模拟，不调用真实模型；真实画质由用户验收。

## 原图生图整板契约（继续保留）

状态：本地实现与离线/隔离联调完成，真实画质待用户验收；接续已完成的03B，不创建新表或通用引擎。

- 输入：确认主图、项目风格快照、image-edit绑定、配置的图片尺寸。新purpose=board，一次图生图输出单张正面/严格侧面/背面板，不附加主图正面构图提示词、不调用文本模型。
- 尺寸：使用用户配置，不提高分辨率；要求正方形或横版（宽高比1至2.5），单边256至5760，PNG/JPEG/WebP且符合H3字节限制。未配置合适尺寸或不支持编辑在排队前拒绝。当前只有wan26-image协议支持真实编辑，模型别名仍按配置处理，不偷偷切换供应商。
- 记录：复用image-jobs、outbox、保存的模型版本和恢复；只有一个board-candidate步骤。候选存referenceBoardCandidate，旧referenceBoard保留。
- 确认：POST characters/{id}/reference-board/approve，candidateId+expectedVersion。在同一存储事务检查项目版本、角色所有权、候选来源主图/外观/服装/风格并替换referenceBoard；同一候选重复确认无副作用。读取和确认无需模型绑定可用。
- 来源：新板记录生成方式、主图版本/对象键、外观服装和风格；源改变后拒绝确认，已付费结果留在图片作业。编辑主图提示词不使已生成板无故失效。视频只读取已确认且来源有效的板，候选不得进入。
- UI：显示候选、确认、显式重新生成；展示已确认/失效板。新入口不用三次分图；旧三图素材及在途任务保持读取和恢复。
- 失败：既有任务只查原任务；提交未知不重发；字节损坏或尺寸非法不安装候选，保留诊断；存储临时失败允许只恢复落库。无自动生成或自动质量打分。
- 验收：先失败测试，再后端全量/前端构建与离线浏览器；隔离PostgreSQL/Redis/Celery/MinIO覆盖带主图的单次提交、恢复、确认及下游选图。真实模型调用0。业务0004升级、运行服务更新和真实画质由后续安排，不能把本地通过当已上线。
