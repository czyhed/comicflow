## 3. 建议的最小漫剧契约

这是设计起点，不是本轮已创建的数据库或类型：

- 创作设定：故事文本、可选参考图片、目标时长、镜头数偏好、风格快照。纯故事输入不能强制要求商品图/视觉模型。
- 角色：稳定 ID、名字、身份/外观/服装、参考资产版本。优先复用原图片/套图卡片和参数抽屉。
- 镜头：稳定 ID、展示顺序、sceneId、characterIds、画面与动作、dialogue、narration、soundscape、durationSeconds、参考/接续模式。
- dialogue 与 narration 必须独立，明确无台词时可同时为空；环境声不冒充旁白。源剧本 ID 若采用，先校验唯一性；展示序号不可作身份。
- 角色图可绑定多镜。角色更新不覆盖历史资产，受影响镜头显示输入过期；选择新结果与自动重新生成分开。
- 输出候选以 assetId/任务记录稳定关联，当前选用版本单独保存。拖动画布或缩放不使生成结果过期；改生成输入才影响对应结果/依赖。
- 时长依据选中模型能力校验，不能悄悄截短对白或把 12 秒保存成 10 秒。用户设置、实际请求、结果展示使用同一单位与含义。
- 同场景连续动作可选指定上一镜视频的真正尾帧；跨场景允许独立参考，不把所有镜头锁死成单一路径。严格首帧与角色参考冲突应先提示。

不要先建庞大的通用工作流引擎、角色市场或跨项目协作系统。

## 4. 分批工作与验收

落地为本地 issue 时遵守 C 的单 feature spec + 独立 issue 文件约定，见 `docs/agents/issue-tracker.md` 和 `triage-labels.md`；本交接不是合并式 issue 文件。每个行为修改先 RED，再实现，再回归。下列批次是实施顺序，全部完成才满足整套产品目标。

### A. 冻结体验基线与可运行环境

输入：上述 donor 版本及用户认可的演示范围。

输出：独立源码副本、来源清单、目标架构记录、依赖锁定方式、原版页面/流程基线。

验收：在隔离环境构建前端；后端使用独立测试配置；验证登录、首页、项目库、模型页、配方列表/详情/编辑/应用、画布节点/连线/撤销/保存/恢复、Studio 准备/制作、拼接/后期/导出。以 fixture/假模型验收交互，截图覆盖桌面和窄屏。若源码与演示不同，列差异而非猜做一版。

### B. 故事、分镜与画布闭环

输入：无商品图的中文故事、可选角色参考、所选风格。

输出：漫剧文本计划、稳定角色/场景/镜头数据、画布分镜编辑与保存、原有图像/视频节点链路。

主要位置：I-S `app/services/executors/text.py`、`prompts.py`、`prompt_skills.py`、`app/prompts/`；I-W `src/canvas/store/node-types.ts`、`sync.ts`、`hooks/useNodeRun.ts`、分镜/文本/镜头面板。

验收：双角色双场景 fixture 含对白镜头及无台词镜头；至少两种镜头数（如 2 与 6）证明不是三段模板；解析→人工编辑→保存→刷新→生成请求→合成输入保持字段、稳定 ID、时长与顺序。错误结构先拒绝并保留草稿，不自动付费修复。修改连线确实改变请求输入，不仅改变 UI。

ComicFlow 来源：`providers/message_contract.py`、剧本相关 fixture、`providers/character_prompt.py`、漫剧写作提示词。提取规则而非整个 pipeline。

### C. 角色、H3 和风格配方

输入：B 的镜头及角色身份、选定参考资产、模型参数和配方。

输出：原画布/素材体验内的角色参考与文字整板；漫剧 H3 请求；原配方页内的漫剧风格。

主要位置：I-S `app/services/executors/image_set.py`、`shot.py`、`providers/xiangong_h3/`、`assisted/style_context.py`、`app/data/`；I-W 角色所用节点/参数抽屉与 `pages/workspace/recipes/`。C 来源见评估报告第 6 节。

验收：两角色引用名与真实图片一一对应；换角色参考不串人、不覆盖旧结果；中性布光的身份图与项目画风用途分开；有对白/无对白提交内容正确；预览与实际 multipart 参数一致；不重复编译提示词；0.5P 等显示项必须与实际像素一致，不能仅换标签。首帧/多参考冲突在调用前拒绝。

风格卡不能只显示选中：所选风格需进入画布与 Studio 的实际创作请求，保存其版本，不强制把所有漫剧套成商品节拍。先选少量代表风格验证，再迁其余；收藏/自定义/应用等原交互保留。

### D. 一键 Studio 漫剧化与后期

输入：同一漫剧契约；复用已有 setup/review/production/compose/arrange/done 页面。

输出：可变镜头计划→人工编辑→逐镜制作/选择→拼接→音轨字幕→导出。

主要位置：I-W `pages/one-click/steps/SetupStep.tsx`、`types.ts`、`film.ts`、`film-state.ts`、`requests.ts`；I-S `api/studio.py`、`services/studio_resume.py`、`executors/assisted/reference_film.py`、`creative_authoring.py`、`creative_contracts.py`、`creative_model.py`。不要误接 retired 的旧 production/pipeline。

拆开商品观察/固定模板与通用渲染、恢复、合成。漫剧不能继续要求 productAnalysis/卖点，不能通过给商品字段塞假值来过校验。用明确 workflow/schema 版本区分旧商品状态与漫剧，保留旧媒体可读；旧 checkpoint 不得误执行为新漫剧任务。

验收：2/6 镜、多场景、无图故事均可准备；不固定 24 秒、不自动加入品牌口号；编辑对白与角色后请求一致；镜头 reorder/插入后，恢复结果按稳定 ID 对应，不按数组位置覆盖人改内容。逐镜失败只恢复该镜，已完成视频继续可用。完成不自动等于用户采用；选择具体版本后能进入原后期界面。

合成验收：选中片段顺序/入出点与真实时长一致，视频和原声同步裁剪；音轨拖动、淡入淡出、字幕位置/样式真实影响 FFmpeg 输出；无台词片段不生造语音。H3 原声没有词级时间戳时，不把按时长分配字幕宣称为语音对齐。保留原可见能力，不删除按钮掩盖未接通功能。

### E. 恢复、保存和真实使用门槛

该批相关 RED 测试应随 B–D 编写；缺陷修复必须在真实付费试用前完成，不是最后才发现的附加优化。

1. 原子画布保存：两个窗口读 v1，同时保存，最多一个成功，另一个 409；前端保留其草稿并显式冲突处理，不换版本重试覆盖。Studio 原行锁保留。
2. 已知远程 ID：超时/重启后恢复只 GET/poll，不再 POST；本地失败不取消/删除尚未知结局的付费任务。
3. 未知提交：请求可能已到供应商却无 ID 时，显式保留未知状态，不能自动重新生成。UI 复用现有错误/恢复区域。
4. 成功但下载/存储失败：保存 remote ID/结果引用，可继续保存；不得再调用生成。
5. 作业创建后进程退出：数据库记录仍可发现；隔离环境验证恢复。若引入执行器/租约/outbox，只改作业执行模块，保留 donor 外部接口，不双跑两套消费者。
6. 取消：分别表示停止后续步骤与已提交远程取消，不暗示一定退款或立即停费。
7. 密钥：模型页保留，API 不回传原值；保存/编辑空密钥的语义明确；必要的服务端加密参考 C SecretCipher，密钥缺失不能静默换新。
8. 登录：固定凭据改成受控配置，默认拒绝未配置；已存在会话机制继续使用。多租户另立范围。

校验方法：真实隔离 PG 双连接测试保存和作业互斥；mock HTTP 记录 POST/GET 次数；模拟 API/执行器中断；登录与模型响应契约测试。实际 schema 变更只能应用到隔离测试库，本机/线上业务库另行授权。
