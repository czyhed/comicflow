## 目标和数据范围

目标是已经选定的宝塔服务器外部 PostgreSQL、Redis、MinIO，采用专用数据库、私有桶和命名空间，不创建一套与其他项目争抢端口的默认数据服务。前后端同机部署；实际地址、目录、账号权限、已有数据、网络和磁盘空间在正式实施前重新核对。

| 内容 | 迁移方式 | 保护与验收 |
| --- | --- | --- |
| PostgreSQL | 16版客户端的 pg_dump / pg_restore | 当前0004的7张表及模型配置自增序列，所有项目/角色/作业/outbox/配置历史；比较数量、完整行摘要和序列状态 |
| MinIO媒体 | 整个专用桶按原对象键备份与恢复 | 当前、候选、失效历史、角色板、场景、首尾帧、视频、音频及已有导出；比较SHA-256、元数据和标签 |
| 模型配置主密钥 | 原密钥单独受保护保存 | 目标全部配置历史可解密；不生成新密钥替代、不输出内容、不请求模型 |
| Redis | 先盘点，使用空目标命名空间 | 不复制旧消息、锁、缓存或Beat文件；在途/未知作业、未发布outbox及队列等先解决 |
| 运行配置 | 独立核对并注入部署环境 | 外部入口使用Drone Secret backend_external_env；API/Worker/Beat最终必须一致 |

本机最近已记录升级到0004，但正式迁移仍以实时只读盘点为准。Docker数据卷不在源码目录，不复制运行中的数据库目录或整个Docker虚拟磁盘，不直接搬MinIO内部.minio.sys。桶策略、生命周期、服务端加密和账号权限由目标运维配置，工具不自动复制；版本桶需要另定方案。

数据和密钥经受保护的SSH/SFTP等通道传输，不进入Git、镜像或构建日志。代码回溯点不能代替数据库和媒体备份。

## 正式实施顺序（尚未执行）

1. 复用已完成的15D和拆分后回归证据，检查此后新增修改并固定发布版本，不重做限定拆分。若schema或存储契约变化，先更新迁移工具并重做对应演练。当前工具只恢复0004，不隐式运行Alembic升级。
2. 用户明确恢复部署并安排停写窗口；重新核对服务器和现有数据，为恢复分配独立空库/空桶/空Redis命名空间。不要覆盖曾用于空服务验证的已有表。
3. 在明确的源上执行只读 inventory。检查全部媒体、模型历史解密、作业、outbox和Redis；仅URL或本地路径的媒体列为阻塞项，不批量替换URL，不自动补生成。
4. 暂停部署和新操作，等待供应商在途任务结束并保存，再停止全部写入者和消费者。unknown状态先核查，不自动取消、重发或标完成；无法确认则延期。数据服务保持可读。
5. 停写窗口执行 backup --writers-stopped。数据库共享只读快照，媒体逐对象备份，前后复核，完整成功才写manifest；原密钥在备份目录外单独保存。报告存在用户数据，限制读取权限。
6. 传输备份和独立密钥，核对目标label后执行 restore。恢复前验证校验和、密钥、目标为空；数据库事务恢复后写对象。失败保留现场和源环境，不自动清空或覆盖，改用新空目标处理。
7. 执行 verify：表和序列、对象内容/元数据、全部配置解密一致，目标Redis命名空间为空。工具不启动API/Worker/Beat。当前外部部署脚本 deploy/backend-external.sh 只读检查schema并默认启API，不会帮忙初始化/升级表或启消费者；旧内置部署脚本不是本次恢复入口。
8. 配置目标内部MinIO地址及可访问的 S3_PUBLIC_ENDPOINT/代理路径，重新签发媒体地址。内部地址按宝塔实际网络确定，不能套用历史 object-store:9000。仅URL无对象键的资产须先人工修复，不改域名冒充签名有效。
9. 受限入口启动API和前端，只读验收项目、角色图、视频历史/候选、播放和已有导出下载，并验证API重启后的恢复。暂不启动消费者、不点连接测试或生成；恢复的模型控制台用途绑定可能覆盖环境mock设置，不能据此假定模型调用已禁用。
10. 验收后明确启用新端写入和隔离命名空间的Worker/Beat；旧端保持停止，避免双写。保留源环境和备份，记录代码版本、数据基线、配置来源及切换时间。

## 回退和完成标准

目标尚无新写入时，关闭目标写入口/消费者，核对没有新增外部任务后回到完整保留的源环境。已有新写入或新付费请求时先冻结并备份新端、核查差异与任务，不能直接切回旧库。工具不会自动做跨环境合并或回退。

正式完成要求：项目/角色ID和版本一致；当前、历史、候选资源均可在新地址读取；库与媒体清单一致；配置历史解密且API重启可恢复；已有导出可下载；旧队列无重放；迁移验收0模型调用；代码和数据都有回退记录。当前合成样本的演练耗时不能估作真实停机承诺，空间需求和时间需正式数据盘点后评估。
